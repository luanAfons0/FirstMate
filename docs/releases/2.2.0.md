# FirstMate 2.2.0

FirstMate is a local plugin host: one App, for Windows and Linux, that gives each of your own tools a process, a page and an address. This version fetches a Plugin as a Plugin Release, a numbered archive its author built, and adds the Process View, which shows what each Plugin uses.

## What changes

- **Plugin Releases.** `firstmate install <git URL>` and `firstmate install <official name>` fetch the newest Plugin Release of a Plugin on GitHub, check its SHA-256, and unpack it into the Shelf ([ADR-0033](../adr/0033-a-git-url-is-fetched-as-a-plugin-release.md)).
  - A Plugin with no Plugin Release, or one not on GitHub, is cloned as before, and `install` says so in one line.
  - `firstmate update <name>` takes the newest Plugin Release with the same MAJOR. It replaces the Release Files and keeps every other file, which is the Plugin's own data. A new MAJOR needs `firstmate update <name> --major`.
  - `update` changes nothing when a Release File was changed or is missing, or when a file of your data is where a new Release File goes. A move that fails part way puts the old files back.
  - `firstmate list` and `firstmate status` show, for each Plugin, its Release Version, `clone` or `copy`.
  - A Plugin author publishes a Plugin Release by pushing a tag `vMAJOR.MINOR.PATCH`. The [Plugin guide](../plugin-guide.md#publish-a-plugin-release) has the workflow to copy.
- **The five Official Plugins ship Plugin Releases.** `worklog`, `scheduler`, `nexus`, `research` and `scribe` publish `0.1.0`, with their Plugin Server bundled into one `mcp.js`. Four of them start in less than half the time, and a `nexus` tool call takes about 110 ms instead of 345 ms.
- **The Process View.** The App's own page shows every Plugin's state and Usage, CPU against one core and fair-share memory, and FirstMate's own Usage first. Open it from the strip or the Tray. The Host reads Usage when asked and keeps none of it ([ADR-0032](../adr/0032-the-host-reads-usage-when-asked.md)). `firstmate usage` and `GET /processes.json` give the same numbers.
- **On Linux each Plugin Server leads its own process group.** When it stops, the rest of its group stops too.

## How to move an installed Plugin to its Plugin Release

A Plugin you installed before 2.2.0 is a git clone, and `firstmate update` still moves it forward as before. FirstMate does not turn a clone into a Plugin Release, because it cannot tell a clone's data from its code. For each Plugin you want to move:

1. Copy its data out of its directory, such as `worklog.db`.
2. Remove it, and install it again:

   ```sh
   firstmate remove worklog
   firstmate install worklog
   ```

3. Put its data back into the new directory, and give its Grants again with `firstmate grant`.

## Known

- The App is still not signed. Windows may say the App is unknown; select **More info**, then **Run anyway**. See the [README](../../README.md#windows-says-the-app-is-unknown).
- FirstMate holds no GitHub token. GitHub allows 60 calls an hour from one address; past that, `install` and `update` say when to try again. A private Plugin is cloned with your own git login.
- The Process View was checked by hand on Linux only.
